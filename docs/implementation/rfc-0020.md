# RFC-0020 implementation record

The six stages follow docs/rfc-0020-five-claims-the-engine-can-already-make.md.
Each stage is committed and pushed separately after its relevant checks.

## Stage 1 — evidenced state-model export

- Filter template sentinels from the persisted model and the report view.
- An unrelated database/network write cannot alone invent a refund edge: effective-refund provenance is restricted to refund-associated symbols.
- `Fact` means the cited static name/effect association exists, not that the transition was observed or that money returned. The domain caption makes this explicit.
- `cie state-model PATH --json`; additive optional snapshot and TypeScript fields; revision-scoped state-model.json artifact.
- Tests cover template-only/unrelated writes, sentinel removal, persistence, no-op materialization, deletion and legacy deserialization.

## Stage 2 — cited Git provenance

- Extracted the existing history implementation verbatim into `cie-history`, re-exported at `cie_ingest::history`. This avoids the proposed `cie-analysis -> cie-ingest -> cie-analysis` cycle and lets contract/claim types reuse `CommitMeta` without depending on ingestion.
- Conformance owns claim binding; the analysis producer calls it after all findings exist. Drift binds its own claims before persistence. Existing analysis callers without a repository retain absent history.
- Production binding requests only distinct cited lines, capped at 64 sites / five seconds. Shallow repositories, unavailable Git, dirty lines and sites beyond the budget remain `None`.
- The additive `introduced` field means blame-derived commit metadata, not a proven full semantic-introduction ancestry. No author/commit is invented. Normalized document lines must match original text before blame is used.
- Targeted crate suites and a real-Git producer integration test pass, including non-repository and dirty-line cases.

## Stage 3 — obligation/test reachability

- Add backwards-compatible `Contract.verified_by` and populate it inside conformance.
- One reverse call index per run; cycle-safe multi-source BFS capped at six edges, deterministic test IDs, parsed `SymbolKind::Test` respected even for non-test-like names.
- This is static reachability, not an execution, assertion, coverage percentage or guarantee of the obligation.
- Regression tests cover direct/transitive callers, cycles, six/seven-edge boundaries, absent callers and legacy JSON.

## Stage 4 — static cross-service declarations

- Add defaulted destination/line/request fields and a defaulted `crossService` array.
- Feign reads named routing attributes (not an arbitrary first quoted contextId); an explicit URL overrides discovery name.
- Run the join after composite merge. Source and destination are cited. Literal HTTP verb/path declarations refine the service match; an ambiguous endpoint/service produces a note, never an arbitrary first route.
- URL joins require a uniquely parsed host identity; unknown hosts, dynamic placeholders and unimplemented local-port/config mappings remain unresolved. Path coincidence alone does not prove a remote destination.
- RestTemplate/WebClient/Kafka presence remains visible with absent targets. The patch does not claim observed invocations.
- The tracked polyglot fixture now declares Java Feign -> Kotlin billing. Tests exercise both citations, named attributes, unmatched/ambiguous targets and legacy JSON.

## Stage 5 — bounded static-model fault planning

- `lineage_from_evidenced` derives only non-template edges, retaining symbol/effect provenance.
- `cie fault PATH --json --max-faults 1|2 --budget-ms 0..5000` persists revision-scoped fault.json. Empty-model and timed-out outcomes remain explicitly Unknown.
- Implementation correction to the RFC snippet: simply plugging the old `SimInjector` into the new graph would still execute its hardcoded debit/ledger demo and evaluate the planner's hardcoded balance_update terminal. A separate `StaticModelInjector` now traverses the actual supplied graph and adapts its selected goal to that internal success marker. The existing planner and fixture injector remain unchanged.
- No runtime or external effects are executed. The report explicitly labels the static model, deterministic first-transition selection and logical experiment counters. Scheduler hypotheses are withheld because no scheduler is evidenced by the payment template.
- Fault/CLI suites pass serially, including real command round-trips, absence, zero-budget timeout and argument bounds. A concurrent drift-cache timing assertion failed once; its serial rerun passed without weakening the test.

## Stage 6 — consumers and reproducible samples

- Promises/Trust show only nonempty evidenced transition views with the fixed payment-template/static-evidence caption and source links. `Fact` is displayed literally: the generic existing `CertaintyChip` maps it to “Proven”, which would overstate what this template establishes.
- Promises exposes engine test bindings and exact test source links, differentiating missing legacy bindings from an explicit empty result. Atlas uses engine bindings where available and clearly labels its legacy fallback.
- Finding/Quality views show optional Git provenance without changing authority or measured metrics. Trust shows document provenance and explicitly simulated fault reports; mismatched fault revisions are withheld.
- Atlas consumes `stack.crossService`, opens both exact file/line citations and filters declarations with container scope. Resolution notes remain inspectable.
- Local analysis obtains a bounded fault artifact only when a state model exists. Bundled fault artifacts are attached only for their own revision and static-only execution flags.
- Regenerate static banking/Spring/polyglot artifacts with `python scripts/regenerate-rfc0020-samples.py`. Runtime measurements are deliberately untouched. The Spring fixture's formerly untracked temporary sources were recovered from its shipped source bundle, with a disclosed new representative manifest so regeneration is repeatable.
- Remap/prune new test and state-view references during tombstone compaction. Legacy JSON remains optional. CLI-style absolute document paths now bind only inside canonical repository scope; normalized lines must match original text. Drift cache keys version the new provenance pipeline.

### Validation commands and boundaries

- Rust: `CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0 cargo test --workspace --locked -- --test-threads=1`.
- Components: `cd web && npm ci && npm run test:rfc0020`.
- Browser: install Playwright Chromium (`npx playwright install chromium`), build, then `npm run test:rfc0020:browser`. `CIE_CHROMIUM` selects an installed executable. Restricted CI may opt into `CIE_BROWSER_SINGLE_PROCESS=1`; that mode tests trusted local UI, not browser sandbox security.
- Production build: `NEXT_TURBOPACK_EXPERIMENTAL_USE_SYSTEM_TLS_CERTS=1 NEXT_TELEMETRY_DISABLED=1 npm run build` (system certificates are needed in this environment).
- The default full TypeScript check encounters an unchanged, unused `src/lib/db.ts` Prisma stub: the repository has no Prisma schema/generated client. Application paths excluding this stub were checked separately; project type-check settings were not weakened. The pre-existing Next configuration already sets `ignoreBuildErrors`.
