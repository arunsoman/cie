# RFC-0024 implementation record

The per-stage validation record (pattern of `docs/implementation/rfc-0022.md`).
RFC-0024 §4 is the stage plan; each section below records what landed, the
verification actually run, and anything the stage deliberately did NOT do.

## Stage 0 — the three contract patches + catalog kinds + gate checks

**Landed (commit range recorded in git history):**

1. **Patch 1 — `RenderHandle.onSelection` / `setSelected`** (`viz-adapter/src/types.ts`):
   the render-handle surface gains `onSelection(cb): () => void` and
   `setSelected(ids, origin)` with the new `SelectionOrigin`
   ('user' | 'programmatic') and `SelectionListener` types. The loop-guarded
   semantics are implemented EXACTLY once in `viz-adapter/src/selection.ts`
   (`createSelectionHub`, headless-pure): identical sets never re-fire
   (echo suppression, counted), re-entrant calls from inside a listener are
   coalesced into one deferred pass (depth cap 1, dropped calls counted) —
   an engine click-echo cannot loop by construction.

2. **Patch 2 — `HiddenCandidate.label` + `.kind`** (`types.ts`) and the G1
   disclosure rows (`disclosure.ts` `hiddenRows()`): rows fall back to
   `id`/`unknown` when the producer recorded no patch-2 fields and DISCLOSE
   the fallback (`fallback: true`) — never a blank row, never a re-order.

3. **Patch 3 — `fields.bodyLines[]` gate rule + `fields.alsoEvidence[]`**
   (`types.ts` `BodyLine`, `gate.ts` `gateFields()` wired INTO `gate()` so
   there is no bypass; `errors.ts` codes `BODY_LINE_WITHOUT_EVIDENCE`,
   `ALSO_EVIDENCE_MALFORMED`). Rule: every body line carries its own
   well-formed EvidenceRef (non-empty file, end ≥ start ≥ 0); every
   alsoEvidence ref is well-formed (paired popups never draw a blank
   column). Elements without these fields are untouched — additive only.

4. **Catalog** (`catalog.ts`): `C10 Component board` registered (Custom —
   the g6 node-kind budget is spent exactly on RFC-0024's four kinds:
   process/decision/store/board-card), plus the per-kind drill/filter
   action matrix (`ChartAction`, `CATEGORY_DEFAULT_ACTIONS`, `actionsFor()`)
   per ux-spec §3/§8: structural/architectural boxes drill, code-level and
   statistical cells filter (a line is a fact, not a scope); the board
   card never scopes.

5. **Rust gate mirror** (`cie-viz/src/gate.rs`): `GateCode::
   BodyLineWithoutEvidence` / `AlsoEvidenceMalformed` with the identical
   stable strings, the identical well-formedness rule (`well_formed_ref`),
   both checks run inside `validate()` (no producer bypass), + 6 Rust tests.

**Verification actually run:**
- `vitest run` (viz-adapter): **301 passed / 0 failed** — the 274 pre-existing
  tests stay green, +27 new (renderhandle.selection 8, hidden.disclosure 5,
  gate.bodylines 12, and the updated catalog audit rows).
- `tsc --noEmit` (viz-adapter): clean.
- `cargo test -p cie-viz`: **29 passed / 0 failed** (23 pre-existing + 6 new
  gate tests).
- `catalog.audit.spec.ts` updated from 76→77 with the C10 registration named
  in the comment — the PRD's frozen enumeration gains exactly one
  registration, which is how the catalog says kinds arrive (the registry is
  the enumeration of what CAN exist).
- Pre-existing breakage repaired in passing: `cie-viz/src/produce.rs` test
  initializer was missing the `concepts_tier` field the WIP hierarchy commit
  added to `RevSnapshot` — the crate did not compile before this stage.

**Deliberately not in stage 0:** the g6 engine's node-kind map
(process/decision/store/board-card) is stage 1; no producer emits bodyLines
or alsoEvidence yet (that is stage 0.5's Pdg/DecisionFact work); the
`HiddenCandidate` label/kind emission in Rust producers lands with the
stage-0.5 producer changes so the G1 popup has real rows to draw.

## Stage 0.5 — engine emissions (flow-chart producer, DecisionFact java+python)

**Landed:**

1. **DecisionFact emission (java)** (`cie-adapter-java/src/lib.rs`): `if_statement`
   handling records `IfSite { symbol, line, cond, cond_vars, loc }` per branch —
   the RFC's `DecisionFact {sym, file, line, cond}` (the file rides the
   LangFacts path; the exact line is `IfSite.line`; the byte span grounds the
   popup). Python already emitted `ifs` (as did kotlin); java was the gap.
2. **Flow-chart producer** (`cie-viz/src/flow.rs`, NEW): `flow_chart(facts,
   store, opts)` over ONE extraction pass emits
   - `process` elements — every callable in the recorded flow (own facts or a
     resolved call target), `fields.file`/`fields.line`/`fields.qualName`,
     evidence = the symbol's byte span through the pass's file table;
   - `decision` elements — ONLY from recorded `IfSite`s (honest absence
     otherwise), `fields.{file,line,cond}`, parent = the owning process;
     module-level `if`s become hidden[] ledger rows, never orphan nodes;
   - `store` elements — recorded sinks (`SqlExecute`, `FileWrite`, …),
     evidence = the owning symbol's span (a sink has no single code line —
     the popup carve-out stays honest), `fields.line` carries the exact line;
   - `calls` / `data-flow` edges from `relation_graph_from_facts` (the
     RFC-0022 §2.1 wiring, now on the production path), resolved calls only —
     unresolved calls never become edges; `writes` edges process → store.
   Salience-bounded cap identical to `from_snapshot` (hidden rows carry
   patch-2 label/kind), footer recomputed, gate-validated + sealed.
3. **`HiddenCandidate.label/kind` in the Rust model** (`cie-viz/src/model.rs`,
   serde-optional, wire-compatible): the concept producer now also stamps
   hidden rows with label/kind — the G1 disclosure popup has real rows.
4. **`extract_revision_files`** (`cie-ingest/src/navigation.rs`, NEW): the
   read-verify-extract core split out of `ensure_navigation` (whose
   cache-first path is untouched) — every source is hash-checked against the
   revision index before extraction; facts are never taken from changed
   sources.
5. **CLI**: `cie viz --flow` produces the flow-chart ViewSpec.

**Verification actually run (the §4 acceptance row):**
- `cargo test -p cie-viz`: 34/34 green (5 new flow tests: file+line on
  process/decision/store, calls+writes edges between drawn elements,
  module-level decisions → ledger rows, unresolved calls never edges,
  cap → disclosed hidden rows).
- `cargo test -p cie-adapter-java -p cie-adapter-python -p cie-relations
  -p cie-ingest -p cie-cli`: all 23 test binaries green, 0 failures.
- **`cie viz samples/polyglot --flow`**: 31 process / **8 decision elements
  carrying file+line** (`BookingService.java:17` `(berth == null)`,
  `:20` `(!berth.isAvailable())`, `BillingService.kt:14`, `Invoice.kt:10`, …),
  1 store, 5 calls + 1 writes edges, footer 40 facts / 0 fog, gate-clean.

**Deliberately not in stage 0.5:** external boxes (compose-YML evidence) are
the stack join, not a LangFacts fact — they join with the web stage's stack
panel; `ControlFlow` statement facts still have no production extractor, so
the Pdg's control-dependence edges stay empty and the FlowChart draws
decisions as recorded branch points, not FOW-computed dominators.

## Stage 1 — the G6 host runtime + render bodies

**Landed:**

1. **Node kinds** (`viz-adapter/src/engines/g6.ts`): `NODE_TYPE` gains
   `process`/`decision`/`store`/`board-card` — the four kinds the extension
   budget was spent on; popup-relevant evidence rides `data.evidence` as
   before.
2. **Host-injected render** (`viz-adapter/src/types.ts` `HostRenderRuntime`,
   `negotiator.ts` `renderHosted()`): the page bundles @antv/g6; the adapter
   package stays headless-pure. The hosted pipeline runs the SAME
   negotiate → gate → adapt → configure sequence as `renderHeadless` (VIZ-09
   still has no bypass — the hosted test proves an ungated spec never
   reaches the host), then calls the host with the adapter-prepared
   options. `G6Adapter.setHostRuntime()` delegates render/relayout when a
   runtime is registered; without one the throw remains the documented
   capability statement.
3. **The web host** (`web/src/lib/viz/g6-engine.ts`, NEW): real
   `render/relayout` bodies generalizing `concept-tree-g6.tsx`'s proven G6 +
   compactBox wiring — tree strategies pre-layout client-side via
   @antv/hierarchy (parents centre on children; height grows with leaf
   count), every other strategy goes to G6's registry untouched; pan/zoom/
   drag behaviors, autoFit/autoResize; every element click fires the
   patch-1 selection surface (loop-guarded, echo-suppressed); relayout via
   the handle's graph reference.
4. **chat-chart bodies via the negotiator** (`chat-chart.tsx`): uml/flow/c4
   now render through `renderViaNegotiator` (DiagramG6) — the ChatChartSpec
   → ViewSpec conversion keeps the producer's discipline (a box without a
   recorded location becomes a hidden[] G1 ledger row with patch-2
   label/kind, never an unevidenced element; narration lines are
   evidence-gated per the patch-3 rule; edges ground in their source box's
   span; the view is sealed with the adapter's own hash functions). The SVG
   painter is DEMOTED to the parity harness behind one honestly-labelled
   toggle — deletion is stage 6.
5. **Packaging**: viz-adapter became a web `file:` dependency with a TS
   `exports` map + `transpilePackages` + `turbopack.root: ".."` (the repo
   root is the workspace root); internal imports went extensionless so the
   same sources serve vitest and Turbopack.

**Verification actually run:**
- `vitest run` (viz-adapter): **305/305** (4 new hosted-pipeline tests:
  order of operations, gate still un-bypassable on the hosted path,
  handle selection surface end-to-end, adapter-without-runtime throw).
- `tsc --noEmit` (viz-adapter + web): clean.
- `next build` (web): **compiled successfully** — the negotiator path is

**Deliberately not in stage 1:** the tree kind still renders through

## Stage 2 — planSheet + presets + slice + the persona sub-menu

**Landed:**

1. **The five PersonaPresets** (`web/src/lib/atlas-presets.ts`, NEW) per
   charter §3's pure-template shape: `id/label/purpose/defaultFactsOnly/
   hero/planOrder/defaultScope` — fresher (facts OFF, orientation-first
   order), reviewer (facts ON, writes-first), architect (facts OFF, full
   detail), auditor (facts ON, routes + cross-boundary writes), consultant
   (fresher + auto-focus, behaves-as-reviewer with a change context). The
   agent persona is honestly absent (§9) — the menu says so in plain words.
   Per-persona `sessionStorage` memory helpers (§14.2-4).
2. **planSheet** (`web/src/lib/chart-plan.ts`, NEW): the pure planner —
   `planSheet(personaId, {factsOnlyOverride, detail})` returns hero + R3
   rows in reading order, each with the drill/filter action row (mirroring
   the catalog matrix) and the charter's one-line "why this panel for THIS
   persona". The user's facts-only override beats the preset default
   (§14.2-3).
3. **slice + re-gate** (`web/src/lib/viz/slice.ts`, NEW):
   `sliceViewSpec(view, {keepIds, factsOnly})` — parentId-closure slicing,
   REGATE (non-Facts drop with a disclosed count), footer recomputed from
   the FINAL set, then the adapter gate re-run ONCE with the shared stable
   codes (a failing slice is a NAMED result, never a blank panel).
4. **The persona sub-menu** (`web/src/components/cie/atlas-persona-menu.tsx`,
   NEW): `Atlas ▾` labeled with the active persona; five entries with
   per-line purpose text; check-mark on active; 1–5 shortcuts ONLY while
   open; arrow/Enter/Esc parity; the honest agent-absence footer (§14.1).
5. **Store** (`cie-store.ts`): `persona` + `setPersona` implementing
   §14.2 — switch = re-plan (no reload); container scope survives all
   switches, module/symbol resets; the manual facts-only override wins for
   the session; per-persona sessionStorage memory restores each persona's
   last state; the switch is footer-disclosed (`personaDisclosure`).
   First-run default = Fresher (§14.2-6).
6. **Atlas + topbar**: the R3 grid renders `plan.rows` (reading order,
   hero-wide panels preserved) instead of hand-code; the expanded-panel
   path is unchanged; the disclosure prints under the grid
   (`data-testid="persona-disclosure"`); the topbar hosts the menu.

**Verification actually run:** `tsc --noEmit` clean; `next build`
compiled successfully; the five presets render from plans over the same
panel vocabulary (panel ids the frame can actually draw — a preset never
names a panel the frame cannot render).

**Deliberately not in stage 2:** the Reviewer's change-context picker and
Impact/Drift panels (the CLI verbs land with stage 2 of the RFC's §3.1
`cie diff/timeline` rows — tracked as their own commit when wired); R4
