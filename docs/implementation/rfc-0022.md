# RFC-0022 implementation follow-through

This record describes the follow-through on the implementation already present
at `bba0ccc`. RFC-0022 §13 is the historical audit of that earlier implementation.

## Stage A: revision-safe navigation and embeddings

- Unchanged org ingests now materialize snapshots. Unresolved calls are persisted
  per revision, so cross-repo candidate links survive reloads.
- Missing legacy navigation artifacts rebuild from source only after checking
  revision and content hashes. Existing artifacts are read without reparsing.
- Graph nodes and unresolved callers are remapped to the final snapshot ID space
  after tombstone compaction. File tables are persisted too: cached citations
  retain their paths and lines. Legacy source offsets are recovered only from
  byte-identical source; unavailable offsets remain unknown.
- Trace supports `--kind all`, rejects ambiguous symbols, and reports unseen
  nodes beyond its depth boundary accurately, including depth zero and cycles.
  Help names the four populated production relation kinds. The other six kinds
  remain unpopulated; this work does not invent statement facts or PDG evidence.
- Search exposes explicit provider, offline override, estimated spend cap and
  KNN time budget. The default remains offline. Analysis labeling remains
  offline in a search invocation; provider opt-in applies to embeddings only.
- Embedding artifacts identify their model/endpoint space (endpoint identity is
  hashed, credentials excluded). Provider switches re-embed the entire corpus,
  even at equal dimensions. Legacy unidentified spaces are rebuilt.
- Changed text alone is embedded; deleted records disappear. Invalid response
  cardinality/dimensions/nonfinite values or provider/query failures trigger
  a complete offline corpus/query pairing, never a mixed-space index. External
  spend estimates are charged before requests. The estimate is not a provider
  billing guarantee. JSON states the actual provider and fallback reason.
- No-op search does not rewrite unchanged embeddings. A missing embedding
  artifact is repaired without changing the revision.

## Scope boundaries

MCP tools remain blocked on RFC-0021's real executor. No stub tools are advertised.
Cross-repo matching still uses globally unique short names, not workspace/import
resolution or exported-visibility proof; these are candidate associations and
must not be represented as verified runtime or API calls. The HNSW graph is
rebuilt from persisted vectors for each search; this is not a durable native
HNSW graph or a sharded index. KNN's time budget excludes ingestion, index rebuild
and provider request latency (providers retain their existing network timeouts).

Stage A validation: **42 passed, 0 failed** across `cie-ingest`/`cie-cli`
lib tests and `rfc0022_cross_repo`, `rfc0022_trace`, `rfc0022_search`.
Run: `cargo test -p cie-ingest -p cie-cli --lib --test rfc0022_cross_repo --test rfc0022_trace --test rfc0022_search --locked`.

## Stage B: extraction, bounded traversal and org scale

- JS/TS/TSX exported declarations now keep their JSDoc. Block lines are cleaned
  individually. Detached notes, previous-code trailing comments and non-doc
  Rust/JS comments are not attached as declaration documentation. Go and Rust
  attribute cases remain covered. Seven adapter integration cases pass.
- Org consumers use `org-member.json`, a compact revision-bound projection of
  mergeable concepts, symbol identities and unresolved calls. Legacy stores
  build this projection once. The cache avoids reading unrelated findings,
  summaries and evidence for each unchanged org merge.
- Cross-repo candidates disclose their matching basis and inferred status;
  duplicate calls no longer duplicate edges. Same-label nodes within a single
  repo are not mistaken for a cross-repo concept merge.
- Search identities include file path, qualified name and declaration ordinal.
  A real two-directory same-stem fixture proves all four symbols remain indexed
  and rejoin to the correct source files.
- Trace traversal is shared engine code, bounded to 10,000 visited symbols,
  100,000 scanned edges and a caller-supplied time budget. Depth/time/work limits
  are reported with retained partial hops. Trace citations identify symbol
  definitions, not the individual call-site span.
- A historical-revision regression checks that persisted file tables retain old
  lines after source edits, and missing graphs cannot be rebuilt from new bytes.

### 2,000-file measurement

Fixture: **20 repos × 100 Python files**, each file declaring a helper and caller.
The test now checks complete cold/repeat org-result equality and the unchanged
**5%** acceptance gate (the earlier shipped test allowed 25%). These are synthetic
local measurements, not a promise for arbitrary repositories or deployment disks.

| Build / path | Cold ingest | Unchanged ingest | Ratio | Gate |
| --- | ---: | ---: | ---: | --- |
| Development, full-snapshot org materialization | 6.114 s | 581.696 ms | 9.5% | Failed |
| Development, compact org projection | 6.443 s | 202.325 ms | 3.1% | Passed |
| Release optimization, LTO disabled, 20 candidate links required | 1.431 s | 37.966 ms | 2.7% | Passed |

The repeat path improved by about **65%** in these two runs. The cold/repeat
outputs are checked for equivalence, so returning an empty org is not accepted as
a speedup. Command: `cargo test -p cie-ingest --test rfc0022_monorepo_bench --locked -- --ignored --nocapture`.

### Usage

```sh
cie trace /path/to/repo app.main --depth 3 --kind all --budget-ms 2000 --json
cie search /path/to/repo "checks user permission" --json
# Explicitly exercise the external-provider budget fallback without making a request:
cie search /path/to/repo "checks user permission" --llm-provider ollama --llm-budget-usd 0 --json
```

The default is offline. Search's provider selection applies to embeddings, not
truth, contract verification or concept membership. Read `embedding_provider`,
`fallback_reason`, `timed_out` and trace's `limit_reason` before treating a
result as complete.


The final fixture additionally requires **20 cross-repo candidate links** on the
cold run, and identical links on the repeat run. An org-wide name index avoids
scanning all sibling symbols per unresolved call. The release command used
`CARGO_BUILD_JOBS=2 RAYON_NUM_THREADS=2 CARGO_PROFILE_RELEASE_LTO=false` with
Rust **1.99.1**, because the toolchain's default thin-LTO link failed with an
undefined hidden LLVM symbol in `default_registry`. The repository release
profile was not changed. The earlier development figures precede the additional
20-link assertion; compare build modes with that fixture difference in mind.

The previously interrupted 10,000-vector / 128-dimensional HNSW test also
**passed** in the optimized build (2.35 seconds test runtime), with the original
exact-neighbor/ranking assertions and 50 ms query budget unchanged. Command:
`cargo test --release -p cie-store --test task_059_hnsw --locked task_059_knn_returns_known_neighbor_within_budget -- --exact --nocapture` with the same release environment above.
