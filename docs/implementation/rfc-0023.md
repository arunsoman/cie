# RFC-0023 implementation

The amended stages in §11 are implemented on top of RFC-0024's coordinated
contract/runtime/planner commits through e049fc1. Stage 0 was already present.

## Stage 1 — verify and complete the G6 host

Preserve adapted graph data on the non-tree canvas path. Use the shared
selection hub and bound conflicting reentrant callbacks to one deferred pass;
listeners receive isolated snapshots. Render failures destroy the canvas.
Disclose the adapter's actual negotiated layout, including substitution.

Validation: 306 adapter tests pass; adapter and web TypeScript checks pass.
`node --test web/test/rfc0023.test.cjs` exercises the host with a mocked G6
boundary, verifying that data reaches the graph and programmatic echoes stop.
Live canvas integration is validated in the final stage.

## Stage 2 — sealed sheet planning

Added the engine-level pure `planSheet` API alongside the persona presentation
planner. Chart presence follows actual containment/relations, scoped element
sets and Facts-only preferences; engine selection uses the negotiator's canvas
and interaction capabilities. Narrow viewports reduce chart count, not facts.
Three tests cover deterministic plans, filtering, viewport and gate rejection.
Adapter suite: 309 passing tests; TypeScript passes.

## Stage 3 — per-scope re-gating

Slices preserve ancestry and source coverage limitations, remove out-of-scope
edges, apply Facts-only to edges as well as nodes, and recompute hashes/footer.
Every omitted element is disclosed by name/kind in the hidden ledger; omitted
counts now include scope exclusions. The canvas route re-gates before rendering.
Host and slicing tests pass (2); web TypeScript passes.

## Stage 4 — conductor and plural context

Canvas clicks now reach the Atlas selection callback instead of bypassing it.
The shared conductor broadcasts only valid IDs to peer handles with programmatic
origin; those echoes cannot trigger scope changes. Every selection contributes
a revision-stamped, deduplicated context chip (cap 24). Map and Atlas selections
share the same store; project changes clear chips. Individual removal and an
explicit whole-project action are available above the composer. Source-less
aggregate chips are explicitly disclosed as contributing no code space.
Four regression tests and web TypeScript pass.

## Stage 5 — selection-scoped answering

`scopeDigest` resolves the selected, current-revision code files before either
local answers or the provider path run. It retains stable file indexes, restricts
symbols/findings/contracts/calls and drops mixed-scope concept rollups. Aggregate
exports without selection attestation are withheld, rather than quoted as local
measurements. Empty/stale/source-less selections yield an empty scope, never an
implicit whole-project fallback. The scope header accompanies local and provider
answers; the persistent whole-project action explicitly clears the selection.
Scoped provider requests exclude earlier whole-project conversation turns and
include a strict selection-only prompt. Live whole-project impact requests and
journey cards are bypassed while scoped. Regression suite (5) and TypeScript pass.
