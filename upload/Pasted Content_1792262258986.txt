# PRD: CIE-VIZ-MULTI — Multi-Engine Visualization Platform

**Codename:** CIE-VIZ-MULTI  
**Status:** Implementation-ready  
**Supersedes:** CIE-VIZ (single-engine G6 PRD)  
**Purpose:** Make visualization a first-class citizen of the Code Intelligence Engine across multiple charting and layouting engines, with a single semantic contract, a closed honesty invariant, an explicit negotiation policy, and a complete catalog of every diagram the engine must produce.  
**Source basis:** CIE PRD, `feature-requirements.md`, the G6 PRD, the multi-engine analysis, and the diagram inventory.

---

# Part I — Foundation

## 1. Definition of done

Visualization is native when all six are true:

1. **CIE emits `ViewSpec`** — a semantic graph with epistemic metadata — and no engine reference.
2. **Each engine is an adapter** implementing the same `EngineAdapter` interface.
3. **The negotiator chooses the engine** by capability gate → user preference → size limits → deterministic order.
4. **The adapter enforces honesty once** via `gate(spec)`; renderers never re-check.
5. **Epistemic encoding is preserved or explicitly degraded**, never silently dropped.
6. **The chart catalog is bounded only by registered extensions**, not by a fixed enumeration.

## 2. Actors and decision authority

### 2.1 Engine decision ladder

```text
1. Capability gate       (negotiator, policy — hard, non-overridable)
2. User preference       (UI, bounded by 1)
3. Graph size limits     (negotiator, hard)
4. Deterministic order   (negotiator; g6 → jointjs → reactflow → mermaid)
```

### 2.2 Layout decision ladder

```text
1. User layout choice    (explicit UI selection — highest)
2. ViewSpec.layoutHint   (CIE shape-based suggestion)
3. Adapter auto-select   (graph-shape analysis)
4. Adapter substitution  (if hint unavailable in engine — always disclosed)
```

Layout precedence is inverted from engine precedence because layout is a legitimate preference, while engine capability is a hard renderability constraint.

### 2.3 What each actor may and may not decide

| Actor | May | May not |
|---|---|---|
| **CIE** | Emit `layoutHint` (strategy name only) | Name an engine, name a layout library |
| **Negotiator** | Reject by capability/size, honour user preference when eligible, fall back deterministically | Override user preference when ineligible without disclosure; silently degrade |
| **User** | Pin engine (subject to capability), pin layout, toggle fisheye per view | Bypass capability gate silently; change semantic content by changing engine |
| **Adapter** | Translate layout hint, substitute unavailable layout and report `LAYOUT_SUBSTITUTED`, decline if limits exceeded | Select its own engine; claim a layout was honoured when substituted |

Every override is **disclosed in the UI** as a named decision with a reason.

## 3. Hash split (cache correctness)

This is the correction that makes multi-engine caching work:

```rust
pub struct ViewSpec {
    // … content
    pub semantic_hash: Hash,   // covers elements, edges, groups, gaps, footer, scope
    pub render_hash:   Hash,   // semantic_hash + layoutHint + preferences + engine_id
}
```

- **Cache key:** `semantic_hash` — layout swap does not invalidate content.
- **Render artifact key:** `render_hash` — layout swap produces a new artifact.
- **Audit baseline:** keyed by `(semantic_hash, engine_id, layout_hint_hash)`.

Without this split, the first-chosen layout would become the only stable one, and multi-engine support would be nominal.

# Part II — The `EngineAdapter` contract

## 4. Interface

```typescript
export interface EngineAdapter {
  readonly id: EngineId;                    // 'g6' | 'mermaid' | 'reactflow' | 'jointjs'
  readonly capabilities: CapabilitySet;
  readonly limits: EngineLimits;

  gate(spec: ViewSpec): void;               // throws on unevidenced elements
  adapt(spec: ViewSpec): unknown;           // ViewSpec → engine-native data
  configure(spec: ViewSpec, options: RenderOptions): unknown;
  render(container: HTMLElement, spec: ViewSpec, options: RenderOptions): Promise<RenderHandle>;
  relayout(handle: RenderHandle, layout: LayoutHint): Promise<LayoutOutcome>;
  audit(handle: RenderHandle, spec: ViewSpec): AuditReport;
}

export interface CapabilitySet {
  fisheye: boolean;
  customNodes: boolean;
  customEdges: boolean;
  customLayouts: boolean;
  plugins: boolean;
  interactive: boolean;
  editable: boolean;
  combos: boolean;
  animatedLayout: boolean;
  svgExport: boolean;
  canvasExport: boolean;
  webgl: boolean;
}

export interface EngineLimits {
  maxNodes: number;
  maxEdges: number;
  supportedLayouts: string[];
  unsupportedFeatures: string[];
}

export interface LayoutOutcome {
  requested: string | undefined;
  actual:    string;
  fidelity:  'Exact' | 'Substituted' | 'Unavailable';
}

export interface RenderHandle {
  engineId:     EngineId;
  semanticHash: string;
  renderHash:   string;
  layout:       LayoutOutcome;
  dispose():    Promise<void>;
}
```

## 5. The gate (single honesty enforcement point)

```typescript
export function gate(spec: ViewSpec): void {
  for (const el of spec.elements) {
    if (!el.evidence)                                     throw new VizError('ELEMENT_WITHOUT_EVIDENCE', el.id);
    if (el.displayMode !== 'Fact' && !el.claimId)          throw new VizError('NON_FACT_WITHOUT_CLAIM', el.id);
    if (el.displayMode === 'Hypothesis' && !el.counterArgument)
                                                            throw new VizError('HYPOTHESIS_WITHOUT_COUNTER', el.id);
    if (el.displayMode === 'Fog' && !el.fogReason)          throw new VizError('FOG_WITHOUT_REASON', el.id);
  }
  for (const e of spec.edges) {
    if (!e.evidence) throw new VizError('EDGE_WITHOUT_EVIDENCE', e.id);
  }
}
```

`gate` is called by every adapter's `adapt`. There is no render path that bypasses it.

## 6. Registry and negotiation

```typescript
export interface EngineRequest {
  required: Partial<CapabilitySet>;
  preferred?: EngineId;
  graphSize: { nodes: number; edges: number };
  layoutHint?: LayoutHint;
}

export function chooseEngine(
  request: EngineRequest,
  registry: Map<EngineId, EngineAdapter>
): EngineAdapter {
  const order: EngineId[] = ['g6', 'jointjs', 'reactflow', 'mermaid'];
  const candidates = [...registry.values()].filter(a => {
    for (const [cap, needed] of Object.entries(request.required)) {
      if (needed && !a.capabilities[cap]) return false;
    }
    if (request.graphSize.nodes > a.limits.maxNodes) return false;
    if (request.graphSize.edges > a.limits.maxEdges) return false;
    if (request.layoutHint &&
        !a.limits.supportedLayouts.includes(request.layoutHint.strategy) &&
        !a.capabilities.customLayouts) return false;
    return true;
  });
  if (request.preferred && candidates.some(a => a.id === request.preferred)) {
    return candidates.find(a => a.id === request.preferred)!;
  }
  return candidates.sort((a, b) => order.indexOf(a.id) - order.indexOf(b.id))[0];
}
```

The negotiator is a **pure function**. Same inputs → same output, always. Every fallback is disclosed in the UI as `Preferred: X ✗ (reason) · Rendered: Y`.

# Part IV — Epistemic encoding across engines

## 7. Fidelity levels

| Engine | Fact | Inference | Hypothesis | Fog | Fidelity |
|---|---|---|---|---|---|
| G6 | solid | `lineDash [6,4]` | `lineDash [2,4]` | hatched + `[1,3]` | **Full** |
| JointJS | solid | `strokeDasharray` | finer dash | pattern fill | **Full** |
| ReactFlow | solid border | dashed CSS | dotted CSS | hatched node background | **Full** (custom node) |
| Mermaid | solid | `classDef` dashed | `classDef` fine dash | grey fill only | **Degraded** — no hatched fill |

**Requirement VIZ-V-01:** every adapter's `audit()` returns `EncodingFidelity: Full | Degraded | Unsupported`. The UI must show degraded fidelity as a banner.

**Requirement VIZ-V-02:** the **text outline** (A11Y linearization) is authoritative when fidelity is degraded. It is generated from the ViewSpec, not from the rendered output.

## 8. Layout translation

| Engine | Translation |
|---|---|
| G6 | Pass `layoutHint.strategy` verbatim to `layout.type`; spread `params` |
| Mermaid | `dagre` or `elk` only; substitute otherwise and report `LAYOUT_SUBSTITUTED` |
| ReactFlow | Run Dagre or ELK **before** rendering; pass positions to nodes |
| JointJS | Map to nearest JointJS layout; report substitution |

Every adapter reports `LayoutOutcome { requested, actual, fidelity }`. UI shows a `Layout: dagre (substituted from force)` chip when fidelity is `Substituted`.

## 9. Fisheye

Only G6 has native fisheye. For other engines the adapter declares `fisheye: false`; the negotiator excludes them when fisheye is required. If a user prefers an engine without fisheye and fisheye is *optional*, the adapter may approximate focus+context (ReactFlow contextual zoom; JointJS `PaperScroller.focus`) but must label it `FOCUS_APPROXIMATION`, never `FISHEYE`.

# Part V — Worked example: Flame Graph in G6

## 10. Why G6 cannot do this natively

G6 ships graph layouts (dagre, force, radial, …) that position nodes on a plane. A flame graph is not a graph layout: it is a **rect-in-rect hierarchical packing** where each node's width is proportional to a sample count and its position is determined by cumulative widths of siblings to the left.

G6 has:
- ❌ no `flame` layout in its registry
- ❌ no `flame-frame` node type
- ❌ no native width-proportional placement

G6 has:
- ✅ a **custom layout registration** (`register(ExtensionCategory.LAYOUT, …)`)
- ✅ a **custom node registration** (`register(ExtensionCategory.NODE, …)`)
- ✅ access to node `size` and `style.size` per node

So a flame graph is built by registering **one custom layout** and **one custom node**. This is exactly the extension surface the PRD requires.

## 12. The custom layout

G6 custom layouts extend `BaseLayout` and implement `execute()`. The layout computes `x`, `y`, `width`, `height` for each node and returns new node data with position and size.

```typescript
import { register, ExtensionCategory, BaseLayout, Graph } from '@antv/g6';

class FlameLayout extends BaseLayout {
  id = 'cie-flame';

  async execute(model: any): Promise<void> {
    const { nodes, edges } = model;

    // 1. Build parent→children from edges
    const childrenOf: Record<string, string[]> = {};
    const parentOf:   Record<string, string>   = {};
    for (const e of edges) {
      childrenOf[e.source] ??= [];
      childrenOf[e.source].push(e.target);
      parentOf[e.target]   = e.source;
    }

    // 2. Find root: node with no parentOf entry
    const root = nodes.find((n: any) => !parentOf[n.id]);
    if (!root) return;

    // 3. Root fills the canvas width; height per depth level
    const canvasW = 960;
    const levelH  = 24;
    const rootSamples = root.data.fields.samples;

    // 4. Depth-first pass computing each node's x/width
    const visit = (nodeId: string, depth: number, xOffset: number) => {
      const node = nodes.find((n: any) => n.id === nodeId);
      if (!node) return;

      const width = (node.data.fields.samples / rootSamples) * canvasW;
      node.style = node.style ?? {};
      node.style.x      = xOffset + width / 2;      // G6 uses center-x
      node.style.y      = depth * levelH + levelH / 2;
      node.style.size   = [width, levelH];

      let childX = xOffset;
      for (const child of childrenOf[nodeId] ?? []) {
        const childNode = nodes.find((n: any) => n.id === child);
        if (!childNode) continue;
        const childW = (childNode.data.fields.samples / rootSamples) * canvasW;
        visit(child, depth + 1, childX);
        childX += childW;
      }
    };
    visit(root.id, 0, 0);
  }
}

register(ExtensionCategory.LAYOUT, 'cie-flame', FlameLayout);
```

## 13. The custom node

G6 custom nodes extend `Rect` and render label + size from the datum. The epistemic stroke is preserved.

```typescript
import { register, ExtensionCategory, Rect } from '@antv/g6';

class FlameFrame extends Rect {
  render(attributes: any, container: any) {
    super.render(attributes, container);

    const [w, h] = attributes.size;
    const data   = attributes.data;

    // Label — truncated to fit
    const maxChars = Math.max(0, Math.floor(w / 7));
    const label = data.label.length > maxChars
      ? data.label.slice(0, maxChars - 1) + '…'
      : data.label;

    this.upsert('label', 'text', {
      text: label,
      x: 0, y: 0,
      textAlign: 'center', textBaseline: 'middle',
      fontSize: 11, fill: '#c9d1d9',
      pointerEvents: 'none',
    }, container);
  }
}

register(ExtensionCategory.NODE, 'cie-flame-frame', FlameFrame);
```

## 17. Why this is "not native" but "fully supported"

The flame graph is not in G6's registry. It is built by:
1. Registering a custom layout (`cie-flame`) via `register(ExtensionCategory.LAYOUT, …)`.
2. Registering a custom node (`cie-flame-frame`) via `register(ExtensionCategory.NODE, …)`.
3. Using the same `gate(spec)` honesty enforcement as every other adapter.
4. Preserving the same epistemic encoding as every other node type.

The adapter contains no branching on "flame" — it uses `node.type: 'cie-flame-frame'` and `layout.type: 'cie-flame'`, which are just strings. If a future PRD requires a flame graph in JointJS, a new `FlameLayout` and `FlameFrame` are registered in JointJS's equivalent extension system, and the ViewSpec is unchanged.

**This is the proof that the architecture generalizes**: a chart that G6 does not ship is implemented in ~60 lines of extension code, with no schema change and no adapter change.

# Part VIII — Non-goals

| Excluded | Reason |
|---|---|
| Reimplementing any layout algorithm in CIE | Layout is engine-owned; adapters translate |
| Reimplementing fisheye in non-G6 engines | Only G6 has it; other engines declare `fisheye: false` |
| A fixed enumeration of chart types in CIE | The registry is the enumeration; additions are `register()` calls |
| Chart-specific branching in the adapter | Adapters are generic over `elementKind` and `edgeKind` |
| Enforcing honesty inside each renderer | `gate()` is the single enforcement point |
| Guaranteeing full encoding fidelity across all engines | Fidelity is disclosed; text outline is authoritative when degraded |
| Supporting an engine-specific chart that no other engine can approximate | If no engine can render the semantic shape, the shape is not producible; the negotiator returns a typed error |
| Live syncing of view state across engines | Each engine has its own interaction model; the ViewSpec is the sync point, not the rendered canvas |

# Part IX — One-sentence summary

**CIE emits a semantic `ViewSpec`; a negotiator picks an engine by hard capability gate → user preference → size limits → deterministic order; every adapter enforces honesty once via `gate()`, translates `layoutHint` to its engine's nearest layout and discloses substitution, preserves or explicitly degrades epistemic encoding, and produces a `RenderHandle` whose `audit()` is checked in CI; the chart catalog is bounded only by registered extensions — 76 charts today, of which 68 are G6-native, 4 are G6-custom (UML class, flame graph, ports, actor), and 4 use Mermaid or custom SVG — with `semantic_hash` making layout and engine swaps cache-safe and every override surfaced in the UI as a named decision with a reason.**
